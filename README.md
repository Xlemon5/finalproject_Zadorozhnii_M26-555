# Валютный кошелёк

Учебная консольная платформа для управления виртуальным портфелем фиатных
и криптовалют. Проект оформлен как устанавливаемый Python-пакет.
Окружение, зависимости и сборка управляются через **uv**.

Реализованы этапы 2.1–2.2: классы `User`, `Wallet`, `Portfolio`, регистрация,
вход, пополнение USD-баланса, покупка, продажа, оценка портфеля и получение курсов.
Parser Service ещё не подключён: используются локальный кэш и учебные курсы.

## Установка и запуск

Нужны Python 3.12 или новее и uv. Файл `.python-version` выбирает Python 3.12.
Make необязателен и используется только для сокращения команд.

```bash
uv sync
uv run wallet
```

`uv sync` создаёт `.venv`, устанавливает проект, `prettytable` и Ruff из группы
`dev`. Активировать окружение вручную при использовании `uv run` не нужно.
Точные версии зависимостей зафиксированы в `uv.lock`, который хранится в Git.
Для установки без изменения lock-файла используйте `uv sync --locked`.

Другие способы запуска того же интерфейса:

```bash
uv run project
uv run python main.py
uv run python -m valutatrade_hub
```

После запуска команды вводятся внутри приложения. Сессия действует до `logout`,
`exit` или завершения процесса. Ctrl+C и Ctrl+D также завершают приложение.
После перезапуска нужно снова выполнить `login`.

## Команды

| Команда | Назначение |
| --- | --- |
| `register --username <имя> --password <пароль>` | Регистрация с пустым портфелем |
| `login --username <имя> --password <пароль>` | Вход в учётную запись |
| `show-portfolio [--base USD]` | Кошельки и их общая стоимость в выбранной валюте |
| `deposit --amount <число>` | Пополнение виртуального USD-баланса |
| `buy --currency <код> --amount <число>` | Покупка валюты за USD |
| `sell --currency <код> --amount <число>` | Продажа валюты с зачислением USD |
| `get-rate --from <код> --to <код>` | Прямой и обратный курс с датой обновления |
| `logout` | Завершение пользовательской сессии |
| `help` | Справка |
| `exit` | Выход из приложения |

`deposit` добавлен по согласованию: регистрация создаёт пустой портфель,
а для покупки требуется USD-баланс. Команда начисляет только виртуальные средства.
Покупка списывает `amount × rate` USD и зачисляет `amount` единиц выбранной валюты.
Продажа выполняет обратную операцию. `amount` для `buy` и `sell` — количество
валюты, например BTC, а не сумма долларов.

USD используется как расчётная валюта: его нельзя купить или продать самому себе.
Для его пополнения служит `deposit`. Кошелёк покупаемой валюты создаётся
автоматически при успешной покупке. Продажа требует существующего кошелька
и достаточного баланса. Комиссий нет.

`show-portfolio`, `deposit`, `buy` и `sell` требуют входа. `get-rate` доступен
без входа. Регистрация не выполняет вход автоматически. Неудачная попытка
`login` сбрасывает предыдущую сессию.

Имена чувствительны к регистру и должны быть уникальными; окружающие пробелы
удаляются. Пароль должен содержать не менее четырёх символов, его пробелы
сохраняются. Значения с пробелами заключайте в кавычки:

```text
register --username "Alice Smith" --password "my password"
```

Аргументы можно передавать как `--amount 100` или `--amount=100`.
Повторные и неизвестные флаги отклоняются. Коды валют приводятся к верхнему
регистру; допустимы латинские буквы и цифры с буквой в начале.
Суммы должны быть положительными конечными числами: ноль, отрицательные значения,
`NaN` и бесконечность отклоняются. Ошибки не завершают консоль.

## Пример сеанса

```text
register --username alice --password 1234
login --username alice --password 1234
show-portfolio
deposit --amount 10000
buy --currency BTC --amount 0.05
buy --currency EUR --amount 200
show-portfolio
sell --currency BTC --amount 0.01
show-portfolio --base EUR
get-rate --from USD --to BTC
logout
exit
```

На учебных курсах покупка `0.05 BTC` стоит `2966.8605 USD`.
При неизменных курсах общая стоимость портфеля после покупок и продаж сохраняется.
Суммы хранятся как `float` по условию задания; округление для таблицы выполняется
только при выводе, возможны обычные погрешности двоичной арифметики.

## Курсы и кэш

Единый метод `RateService.get_rate(from_currency, to_currency)` возвращает
словарь с полями `from`, `to`, `rate`, `updated_at`, `source`.
Один и тот же сервис используется при оценке портфеля, сделках и `get-rate`.

Сначала проверяется `data/rates.json`. Курс считается свежим, если ему менее
300 секунд. Для обратной пары используется `1 / rate`, для кросс-курса —
пересчёт через USD. Возраст кросс-курса определяется более старым из двух курсов.
Даты хранятся в ISO-формате с часовым поясом UTC; даты без пояса читаются как UTC.

Если свежего курса нет, заглушка обновляет кэш следующими **учебными значениями**:

| Валюта | USD за одну единицу |
| --- | ---: |
| USD | 1 |
| EUR | 1.0786 |
| BTC | 59337.21 |
| RUB | 0.01016 |
| ETH | 3720 |

Эти значения не являются актуальными рыночными котировками. Источник заглушки
обозначается `Stub`. Свежие пары из локального кэша имеют приоритет.
Другие валюты можно оценивать по свежим данным кэша; если курс устарел
и заглушка его не поддерживает, операция завершится понятной ошибкой.
Повреждённый кэш не заменяется учебными данными автоматически.

## Модели

- `User(user_id, username, hashed_password, salt, registration_date)` хранит
  приватные атрибуты с геттерами. Имя меняется через проверяемое свойство,
  пароль — через `change_password`. `verify_password` проверяет пароль,
  `get_user_info` возвращает словарь без хеша и параметра salt.
- `Wallet(currency_code, balance=0.0)` проверяет баланс и суммы в `deposit`
  и `withdraw`. `get_balance_info` возвращает код валюты и баланс.
- `Portfolio(user_id, wallets=None, *, user)` принимает объект владельца
  с тем же ID. Свойство `user` доступно только для чтения. `wallets` возвращает
  поверхностную копию словаря: изменение состава копии не меняет портфель,
  сами объекты кошельков остаются общими. `get_wallet` возвращает кошелёк,
  повторный `add_currency` сохраняет его баланс.
  `get_total_value(base_currency='USD', exchange_rates=None)` возвращает
  общую стоимость; можно передать курсы к общей валюте вместо учебных значений.

**Salt** — индивидуальный случайный параметр, который добавляется к паролю перед
хешированием. Это общепринятый термин в криптографии. По условию задания хеш
вычисляется как SHA-256 от строки `password + salt`. В JSON сохраняются хеш
и параметр salt, а не исходный пароль. Одинаковые пароли у разных пользователей
дают разные хеши. При смене пароля используется сохранённый параметр salt.

## Хранение данных

При запуске создаётся `data/` **в текущей рабочей папке**:

- `users.json` — ID, имя, хеш пароля, параметр salt и дата регистрации
- `portfolios.json` — ID владельца и словарь кошельков с балансами
- `rates.json` — валютные пары, значения, даты обновления и источник

Чтобы работать с теми же данными, запускайте приложение из той же папки.
Начальные файлы пользователей и портфелей содержат `[]`, кэш — `{}`.
Данные пользователей, окружение, результаты сборки и кэши исключены из Git.

Каждый JSON-файл записывается через временный файл и атомарную замену.
Оба баланса сделки сохраняются одной записью `portfolios.json`.
При неверных данных, недостатке средств или ошибке записи исходные балансы
не меняются. Повреждённые файлы и несоответствие схемы выводятся как ошибки;
исходное содержимое сохраняется для исправления.

Регистрация затрагивает два файла: при ошибке сохранения пользователей выполняется
откат изменения портфелей. Это учебное файловое хранилище для одного процесса:
межпроцессные блокировки и полноценные транзакции на случай аварийного завершения
между заменой двух файлов не реализованы.

## Структура проекта

```text
valutatrade_hub/
├── __init__.py
├── __main__.py
├── core/
│   ├── __init__.py
│   ├── models.py       # User, Wallet, Portfolio
│   ├── utils.py        # Валидация и JSON-хранилище
│   ├── rates.py        # Кэш и учебные курсы
│   └── usecases.py     # Регистрация, сессия и сделки
└── cli/
    ├── __init__.py
    └── interface.py    # Разбор команд и вывод
main.py
tests/
data/                  # Создаётся при запуске
Makefile
pyproject.toml
uv.lock
```

В CLI нет расчётов сделок или прямой работы с JSON: он вызывает методы сервиса
из `core/usecases.py` и выводит результаты через PrettyTable.
Parser Service и история транзакций относятся к следующим этапам.

## Проверки и сборка

| Действие | Через uv | Через Make |
| --- | --- | --- |
| Установка | `uv sync` | `make install` |
| Запуск | `uv run wallet` | `make run` или `make wallet` |
| Альтернативный запуск | `uv run project` | `make project` |
| Линтер | `uv run ruff check .` | `make lint` — обе проверки |
| Проверка форматирования | `uv run ruff format --check .` | `make lint` — обе проверки |
| Форматирование | `uv run ruff format .` | `make format` |
| Тесты | `uv run python -m unittest discover -s tests -v` | `make test` |
| Сборка wheel и sdist | `uv build` | `make build` |

Тесты используют временные папки. Они проверяют модели, изоляцию пользователей,
сохранение данных, сделки, срок кэша, ошибки файлов и реальные запуски CLI.
Это тесты проекта, а не предоставленные преподавателем автотесты.

Сборка и установка wheel на macOS/Linux:

```bash
uv build
uv pip install --python .venv/bin/python dist/*.whl
.venv/bin/wallet
```

Прямой запуск `.venv/bin/wallet` проверяет установленный пакет. Для возвращения
к разработке выполните `uv sync`: изменения исходников снова будут доступны
без переустановки wheel.

Добавление зависимостей: `uv add <пакет>` или `uv add --dev <инструмент>`.
Модули стандартной библиотеки отдельно устанавливать не требуется.
