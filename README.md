# Валютный кошелек

Учебная консольная платформа для управления виртуальным портфелем фиатных
и криптовалют. Проект оформлен как устанавливаемый Python-пакет.
Окружение, зависимости и сборка управляются через **uv**.

Реализованы этапы 2–4: модели пользователей и портфелей, регистрация, вход,
пополнение USD-баланса, торговля, оценка портфеля, иерархия валют, доменные
исключения, Singleton для настроек и хранилища, журнал операций с ротацией.
Parser Service получает котировки CoinGecko и ExchangeRate-API, ведет историю
измерений и обновляет локальный кэш. Торговые операции используют этот кэш.

## Установка и запуск

Нужны Python 3.12 или новее и uv. Файл `.python-version` выбирает Python 3.12.
Make необязателен и используется только для сокращения команд.

```bash
uv sync
uv run wallet
```

`uv sync` создает `.venv`, устанавливает проект, `prettytable`, `requests`, `python-dotenv` и Ruff из группы
`dev`. Активировать окружение вручную при использовании `uv run` не нужно.
Точные версии зависимостей зафиксированы в `uv.lock`, который хранится в Git.
Для установки без изменения lock-файла используйте `uv sync --locked`.

Другие способы запуска того же интерфейса:

```bash
uv run project
uv run python main.py
uv run python -m valutatrade_hub
```

После запуска команды вводятся внутри приложения. Сессия действует до `logout`,
`exit` или завершения процесса. Ctrl+C и Ctrl+D также завершают приложение.
После перезапуска нужно снова выполнить `login`.

## Команды

| Команда | Назначение |
| --- | --- |
| `register --username <имя> --password <пароль>` | Регистрация с пустым портфелем |
| `login --username <имя> --password <пароль>` | Вход в учетную запись |
| `show-portfolio [--base USD]` | Кошельки и их общая стоимость в выбранной валюте |
| `deposit --amount <число>` | Пополнение виртуального USD-баланса |
| `buy --currency <код> --amount <число>` | Покупка валюты за USD |
| `sell --currency <код> --amount <число>` | Продажа валюты с зачислением USD |
| `get-rate --from <код> --to <код>` | Прямой и обратный курс с датой обновления |
| `update-rates [--source coingecko\|exchangerate]` | Загрузить курсы из всех API или одного источника |
| `show-rates [--currency BTC] [--top 2] [--base USD]` | Таблица из кэша с фильтрацией и конвертацией |
| `currencies` | Поддерживаемые валюты с их типом и дополнительными атрибутами |
| `logout` | Завершение пользовательской сессии |
| `help` | Справка |
| `exit` | Выход из приложения |

`deposit` добавлен по согласованию: регистрация создает пустой портфель,
а для покупки требуется USD-баланс. Команда начисляет только виртуальные средства.
Покупка списывает `amount × rate` USD и зачисляет `amount` единиц выбранной валюты.
Продажа выполняет обратную операцию. `amount` для `buy` и `sell` — количество
валюты, например BTC, а не сумма долларов.

USD используется как расчетная валюта: его нельзя купить или продать самому себе.
Для его пополнения служит `deposit`. Кошелек покупаемой валюты создается
автоматически при успешной покупке. Продажа требует существующего кошелька
и достаточного баланса. Комиссий нет.

`show-portfolio`, `deposit`, `buy` и `sell` требуют входа. Просмотр валют,
получение и обновление курсов доступны без входа. Регистрация не выполняет вход
автоматически. Неудачная попытка
`login` сбрасывает предыдущую сессию.

Имена чувствительны к регистру и должны быть уникальными; окружающие пробелы
удаляются. Пароль должен содержать не менее четырех символов, его пробелы
сохраняются. Значения с пробелами заключайте в кавычки:

```text
register --username "Alice Smith" --password "my password"
```

Аргументы можно передавать как `--amount 100` или `--amount=100`.
Повторные и неизвестные флаги отклоняются. Коды валют приводятся к верхнему
регистру; допустимы 2–5 латинских букв или цифр с буквой в начале, без пробелов.
Валютный код дополнительно проверяется по общему реестру.
Суммы должны быть положительными конечными числами: ноль, отрицательные значения,
`NaN` и бесконечность отклоняются. Ошибки не завершают консоль.

## Пример сеанса

```text
update-rates
show-rates --top 2
register --username alice --password 1234
login --username alice --password 1234
show-portfolio
deposit --amount 10000
buy --currency BTC --amount 0.05
buy --currency EUR --amount 200
show-portfolio
sell --currency BTC --amount 0.01
show-portfolio --base EUR
get-rate --from USD --to BTC
logout
exit
```

Стоимость покупки зависит от полученного курса; при нехватке USD уменьшите
количество валюты или пополните виртуальный баланс.
При неизменных курсах общая стоимость портфеля после покупок и продаж сохраняется.
Суммы хранятся как `float` по условию задания; округление для таблицы выполняется
только при выводе, возможны обычные погрешности двоичной арифметики.

## Parser Service: ключи и запуск

Ключ ExchangeRate-API получите в личном кабинете
[ExchangeRate-API](https://www.exchangerate-api.com/). Для CoinGecko предусмотрена
переменная `COINGECKO_API_KEY`: она передается заголовком `x-cg-demo-api-key`, как
описано в [документации Demo API](https://docs.coingecko.com/demo/reference/authentication).
Если ключ CoinGecko не задан, клиент делает публичный запрос; доступ без ключа
не гарантирован. При HTTP 401/403 настройте Demo-ключ.

Для постоянной настройки скопируйте `.env.example` в `.env` в корне проекта
и заполните ключи в этом локальном файле:

```dotenv
EXCHANGERATE_API_KEY=ваш_ключ_ExchangeRate_API
COINGECKO_API_KEY=ваш_Demo_ключ_CoinGecko
```

После этого достаточно `uv run wallet`: `ParserConfig` прочитает `.env` из
текущей рабочей папки при создании. Для CoinGecko можно оставить значение пустым,
если публичный доступ работает. `.env` исключен из Git; в репозитории хранится
только пустой шаблон `.env.example`.

Альтернатива для bash/zsh — задать ключи в текущем сеансе терминала:

```bash
export EXCHANGERATE_API_KEY="ваш_ключ_ExchangeRate_API"
export COINGECKO_API_KEY="ваш_Demo_ключ_CoinGecko"
uv run wallet
```

Вместо шаблонов укажите свои значения локально. Приложение не сохраняет ключи
в JSON, журнал или представление `ParserConfig`. Переменные окружения имеют
приоритет над `.env`, включая явно пустые значения.
Чтение файла не меняет глобальное окружение и не выполняется при импорте модулей.
Запускайте приложение из папки с вашим `.env`.

Внутри кошелька:

```text
update-rates
update-rates --source coingecko
update-rates --source exchangerate
show-rates
show-rates --currency RUB
show-rates --top 2 --base EUR
get-rate --from BTC --to EUR
```

`--top` выбирает самые дорогие **криптовалюты по цене одной единицы**, а не по
капитализации. Без него строки сортируются по коду. Фильтр `--currency` можно
совместить с `--top` и `--base`. Просмотр кэша не обращается к API.

Парсер запускается и отдельно от кошелька:

```bash
uv run rates-parser
uv run rates-parser --source coingecko
uv run rates-parser --watch --interval 300
uv run python -m valutatrade_hub.parser_service --source exchangerate
```

Без `--watch` выполняется один цикл: код выхода 0 означает полный успех,
1 — частичный результат или ошибку. В режиме `--watch` первый цикл выполняется
сразу, затем процесс ждет заданное число секунд после каждого цикла. Ошибки
выводятся и журналируются, следующий цикл продолжает работу. Ctrl+C останавливает
процесс; фоновые службы автоматически не устанавливаются.

Частоту обновления выбирайте с учетом квот своего API-тарифа. Автоматических
немедленных повторов запросов нет, при HTTP 429 нужно дождаться восстановления
лимита или увеличить интервал. Если интервал больше TTL, измените также
`rates_ttl_seconds` под выбранную политику свежести.

## API-контракты и конфигурация парсера

`ParserConfig` в `parser_service/config.py` содержит URL, списки валют,
соответствия ID, пути, таймаут и интервал. API-ключи читаются из окружения
или локального `.env` при создании объекта,
а не при импорте модуля. Словарь ID у каждого экземпляра собственный.

| Параметр | Значение по умолчанию |
| --- | --- |
| `COINGECKO_URL` | `https://api.coingecko.com/api/v3/simple/price` |
| `EXCHANGERATE_API_URL` | `https://v6.exchangerate-api.com/v6` |
| `BASE_CURRENCY` | `USD` — единая база сохраняемых курсов |
| `FIAT_CURRENCIES` | `EUR`, `GBP`, `RUB` |
| `CRYPTO_CURRENCIES` | `BTC`, `ETH`, `SOL` |
| `CRYPTO_ID_MAP` | `BTC: bitcoin`, `ETH: ethereum`, `SOL: solana` |
| `REQUEST_TIMEOUT` | `10` секунд |
| `UPDATE_INTERVAL` | `300` секунд |
| `RATES_FILE_PATH` | `data/rates.json` |
| `HISTORY_FILE_PATH` | `data/exchange_rates.json` |

При обычном запуске `ParserConfig.from_settings()` получает пути, таймаут и
интервал из `SettingsLoader`. При внедрении хранилища используются его пути.
База запросов фиксирована USD; флаг `--base` меняет валюту отображения.

`BaseApiClient.fetch_rates()` возвращает словарь чисел `{"BTC_USD": 60000, ...}`.
`CoinGeckoClient` передает ID монет, `vs_currencies=usd` и
`include_last_updated_at=true`, согласно
[контракту simple/price](https://docs.coingecko.com/demo/reference/simple-price).

`ExchangeRateApiClient` использует `/v6/<ключ>/latest/USD`. У этого эндпоинта
поле называется `conversion_rates`; `rates` из учебного примера тоже принимается.
Котировка в ответе показывает число единиц валюты за **1 USD**, поэтому для
`EUR_USD` сохраняется обратная величина: при `USD_EUR = 0.8` получаем
`EUR_USD = 1.25`. Это исправляет направление курса в примере задания, согласно
[контракту ExchangeRate-API](https://www.exchangerate-api.com/docs/standard-requests).

Оба клиента проверяют HTTP-статус, JSON, наличие всех запрошенных валют и
положительность конечных чисел. Неполный или некорректный ответ источника
отклоняется целиком. Ошибки сети, таймаут, неверный ключ, исчерпание квоты и
ошибки ответа преобразуются в `ApiRequestError`. Тела ошибок и URL с ключами
не включаются в пользовательские сообщения и журналы.

## Кэш, история и свежесть

`RatesUpdater` последовательно опрашивает клиентов и передает валидные измерения
в `ParserStorage`. При отказе одного источника результаты другого сохраняются;
пары отказавшего источника остаются с прежними значениями и датами. Если ни один
источник не вернул корректные данные, оба JSON-файла остаются без изменений.

`data/rates.json` содержит один последний срез каждой пары:

```json
{
  "pairs": {
    "BTC_USD": {"rate": 60000, "updated_at": "2026-10-07T12:00:00Z", "source": "CoinGecko"},
    "EUR_USD": {"rate": 1.25, "updated_at": "2026-10-07T12:00:00Z", "source": "ExchangeRate-API"}
  },
  "last_refresh": "2026-10-07T12:00:01Z"
}
```

`data/exchange_rates.json` — массив измерений, например:

```json
[
  {
    "id": "BTC_USD_2026-10-07T12:00:00Z",
    "from_currency": "BTC",
    "to_currency": "USD",
    "rate": 60000,
    "timestamp": "2026-10-07T12:00:00Z",
    "source": "CoinGecko",
    "meta": {"raw_id": "bitcoin", "request_ms": 124, "status_code": 200}
  }
]
```

Здесь цены приведены только как примеры формата. ID составляется из пары и
времени получения в UTC. Повторное сохранение того же измерения не дублирует
историю. Новый опрос с новым временем — отдельное измерение, даже если цена
не изменилась. В кэш попадает запись с более свежим временем; запоздавший ответ
не заменяет более новый. `meta` также содержит ETag и `provider_updated_at`,
если поставщик передал эти поля.

`timestamp` и `updated_at` — **время успешного получения ответа**, а время
обновления цены самим поставщиком отдельно хранится в `meta.provider_updated_at`.
TTL ограничивает возраст локального получения, а не гарантирует возраст
рыночной котировки: фиатный API может обновлять данные значительно реже.

`RateService.get_rate()` возвращает `from`, `to`, `rate`, `updated_at`, `source`,
`inverse_rate` и `stale`. Кэш свежий, если возраст пары от 0 до `rates_ttl_seconds` секунд
(верхняя граница не включается). Для обратной пары используется `1 / rate`,
для кросс-курса — пересчет через USD и более старая дата двух составляющих.
При отсутствии или устаревании данных `get-rate`, оценка портфеля и сделки
предлагают выполнить `update-rates`. Автоматических запросов API и подстановки
учебных цен в Core Service нет. `show-rates` позволяет увидеть старые записи,
но явно помечает их как устаревшие. Курс валюты к самой себе всегда равен 1.

Старый плоский формат `rates.json` читается для совместимости; при следующем
успешном обновлении он сохраняется в схеме с `pairs`. Записи с источником `Stub`
игнорируются. Учебные константы остались только для отдельного вызова модели
`Portfolio.get_total_value()` без явно переданных курсов и для тестовых примеров.
В приложении модель получает проверенные курсы из кэша.

Парсер блокирует совместную операцию чтения–изменения–записи через файл
`.rates.json.lock` рядом с кэшем. Блокировка освобождается системой при завершении
процесса; CLI и планировщик могут обновлять одни и те же файлы. JSON заменяется
атомарно через временный файл. Сначала сохраняется история, затем кэш: это две
отдельные атомарные записи, не общая транзакция. При сбое второй записи история
сохраняется, а кэш остается прежним; нужно повторить обновление. Поврежденные
данные не затираются, а выводятся как файловая ошибка или ошибка валидации.

`logs/parser.log` содержит JSON Lines с событиями `update_started`,
`fetch_started`, `fetch_succeeded`, `fetch_failed`, `storage_failed`,
`update_completed` и `update_failed`. Записываются UTC-время, источник, число
курсов и причина ошибки. Настройки уровня и ротации общие с журналом действий,
файл отдельный. В CLI выводится итог по каждому источнику и число обновленных пар.

## Иерархия валют и ошибки

`Currency` — абстрактный класс с публичными проверяемыми свойствами `name`, `code`
и абстрактным методом `get_display_info()`. Напрямую создать `Currency` нельзя.
У `FiatCurrency` дополнительно есть `issuing_country`, у `CryptoCurrency` —
`algorithm` и `market_cap`. Наследники реализуют свой формат представления:

```text
[FIAT] USD — US Dollar (Issuing: United States)
[CRYPTO] BTC — Bitcoin (Algo: SHA-256, MCAP: 1.12e12)
```

Команда `currencies` вызывает один и тот же метод у объектов разных классов.
Капитализация и алгоритмы в реестре заданы как учебные примеры из задания,
не обновляются из API и не являются текущими рыночными сведениями.

`get_currency(code)` нормализует ввод и возвращает отдельный объект из реестра.
Изменение этого объекта не меняет описание валюты для остальных пользователей.
В реестре есть USD, EUR, GBP, RUB, BTC, ETH и SOL. Код неизвестной валюты вызывает
`CurrencyNotFoundError`, в том числе при создании кошелька, покупке, продаже,
выборе базовой валюты и запросе курса.

| Исключение | Где возникает | Действие CLI |
| --- | --- | --- |
| `InsufficientFundsError(available, required, code)` | Списание через `Wallet.withdraw`, покупка без нужного USD-баланса, продажа без кошелька или нужной суммы | Печатает сообщение без изменения |
| `CurrencyNotFoundError(code)` | Проверка кода через `get_currency` | Печатает сообщение и список поддерживаемых кодов |
| `ApiRequestError(reason)` | Сбой поставщика или некорректный ответ при обновлении курса | Печатает причину и предлагает повторить запрос позже или проверить сеть |

Примеры сообщений:

```text
Недостаточно средств: доступно 0.0400 BTC, требуется 0.0500 BTC
Неизвестная валюта 'ABC'
Ошибка при обращении к внешнему API: timeout
```

Все три ошибки перехватываются в `cli/interface.py`. Неудачные `buy` и `sell`
не сохраняют изменения портфеля и не завершают консоль.

## Модели

- `User(user_id, username, hashed_password, salt, registration_date)` хранит
  приватные атрибуты с геттерами. Имя меняется через проверяемое свойство,
  пароль — через `change_password`. `verify_password` проверяет пароль,
  `get_user_info` возвращает словарь без хеша и параметра salt.
- `Wallet(currency_code, balance=0.0)` проверяет баланс и суммы в `deposit`
  и `withdraw`. `get_balance_info` возвращает код валюты и баланс.
- `Portfolio(user_id, wallets=None, *, user)` принимает объект владельца
  с тем же ID. Свойство `user` доступно только для чтения. `wallets` возвращает
  поверхностную копию словаря: изменение состава копии не меняет портфель,
  сами объекты кошельков остаются общими. `get_wallet` возвращает кошелек,
  повторный `add_currency` сохраняет его баланс.
  `get_total_value(base_currency='USD', exchange_rates=None)` возвращает
  общую стоимость; можно передать курсы к общей валюте вместо учебных значений.

**Salt** — индивидуальный случайный параметр, который добавляется к паролю перед
хешированием. Это общепринятый термин в криптографии. По условию задания хеш
вычисляется как SHA-256 от строки `password + salt`. В JSON сохраняются хеш
и параметр salt, а не исходный пароль. Одинаковые пароли у разных пользователей
дают разные хеши. При смене пароля используется сохраненный параметр salt.

## Хранение данных

При стандартных настройках создается `data/` **в текущей рабочей папке**:

- `users.json` — ID, имя, хеш пароля, параметр salt и дата регистрации
- `portfolios.json` — ID владельца и словарь кошельков с балансами
- `rates.json` — кэш последних курсов
- `exchange_rates.json` — история измерений Parser Service

Чтобы работать с теми же данными, запускайте приложение из той же папки.
Начальные файлы пользователей и портфелей содержат `[]`. Кэш и история
создаются при первом успешном обновлении курсов.
Данные пользователей, журналы, окружение, результаты сборки и кэши исключены из Git.

Каждый JSON-файл записывается через временный файл и атомарную замену.
Оба баланса сделки сохраняются одной записью `portfolios.json`.
При неверных данных, недостатке средств или ошибке записи исходные балансы
не меняются. Поврежденные файлы и несоответствие схемы выводятся как ошибки;
исходное содержимое сохраняется для исправления.

Регистрация затрагивает два файла: при ошибке сохранения пользователей выполняется
откат изменения портфелей. Операции с пользователями и портфелями рассчитаны на один процесс кошелька;
их межпроцессные блокировки и полноценные транзакции при аварии между заменами
двух файлов не реализованы. Межпроцессная блокировка Parser Service относится
только к файлам курсов.

`DatabaseManager` — единый менеджер доступа к JSON. Методы `load`, `save`,
`initialize` учитывают имена файлов из настроек. Контекст `transaction()`
удерживает общую блокировку `RLock` на время чтения, изменения и записи.
Она защищает операции разных экземпляров сервиса внутри одного процесса;
это не транзакция СУБД с аварийным восстановлением.
При тестировании можно явно передать отдельный `JsonStorage` с временной папкой.

## Настройки и Singleton

`SettingsLoader` и `DatabaseManager` реализованы через `__new__`: повторное
обращение возвращает тот же объект. Этот способ выбран за простоту и читаемость.
Создание защищено блокировкой, при импорте модулей экземпляры не создаются.
`WalletService` по умолчанию получает оба Singleton; сервис курсов использует
настройки TTL, сервис портфеля — базовую валюту, менеджер — пути к данным.

По умолчанию настройки читаются из секции `[tool.valutatrade]` файла
`pyproject.toml` в рабочей папке. Если такого файла нет, используются значения
по умолчанию — это позволяет запускать установленный wheel в любой папке.
Можно явно передать путь к отдельному JSON-файлу с теми же ключами:
`SettingsLoader("config.json")` до создания сервисов.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `data_dir` | `data` | Папка данных |
| `users_file` | `users.json` | Имя файла пользователей |
| `portfolios_file` | `portfolios.json` | Имя файла портфелей |
| `rates_file` | `rates.json` | Имя файла курсов |
| `history_file` | `exchange_rates.json` | Имя файла истории курсов |
| `request_timeout` | `10` | Таймаут API-запроса в секундах |
| `parser_interval_seconds` | `300` | Интервал планировщика |
| `parser_log_file` | `parser.log` | Журнал парсера |
| `rates_ttl_seconds` | `300` | Срок свежести курса в секундах |
| `default_base_currency` | `USD` | База `show-portfolio` без флага `--base` |
| `log_dir` | `logs` | Папка журнала |
| `log_file` | `actions.log` | Имя файла журнала |
| `log_format` | `json` | Формат JSON Lines |
| `log_level` | `INFO` | Уровень INFO или DEBUG |
| `log_max_bytes` | `1048576` | Порог ротации — 1 МиБ |
| `log_backup_count` | `3` | Число резервных файлов |
| `log_verbose` | `false` | Дополнительные данные о балансах |

Относительные пути считаются от папки файла конфигурации; имена JSON-файлов
указываются без пути. `get(key, default=None)` возвращает копию значения,
`reload()` перечитывает и проверяет конфигурацию. При ошибке сохраняются прежние
настройки. TTL и базовая валюта применяются при следующем запросе. Для изменения
обработчика журнала после `reload()` вызовите `configure_logging(settings)`.
Повторное создание Singleton с другим файлом настроек отклоняется.
Валюта расчетов `buy`/`sell` остается USD независимо от базы отображения портфеля.

## Журнал операций

Методы `WalletService.buy` и `WalletService.sell` помечены `@log_action`.
Успех и ошибка записываются на уровне INFO. Декоратор сохраняет имя, docstring
и сигнатуру метода через `functools.wraps`; исключение передается вызывающему
коду без замены. Регистрация и вход сейчас не журналируются.

Файл `logs/actions.log` содержит по одному JSON-объекту на строку. Поля:
`timestamp` (ISO, UTC), `level`, `action`, `user_id`, `username`, `currency_code`,
`amount`, `rate`, `base`, `result`. При ошибке добавляются `error_type`
и `error_message`. Недоступные значения обозначаются `null`.
Пароль, хеш пароля и параметр salt в журнал не передаются.

```json
{"timestamp":"2025-10-09T12:05:22.000+00:00","level":"INFO","action":"BUY","user_id":1,"username":"alice","currency_code":"BTC","amount":0.05,"rate":59300.0,"base":"USD","result":"OK"}
```

При `log_verbose = true` успешная сделка получает `context` с балансами
`before`, `after`, `usd_before`, `usd_after`, а ошибка нехватки средств —
`available` и `required`. Параметр декоратора `verbose=True/False` может явно
переопределить эту настройку.

При достижении порога размера создаются `actions.log.1`–`actions.log.3`.
Более старые резервные файлы удаляются при очередной ротации. Повторная
настройка логирования не добавляет дублирующиеся обработчики.

в `actions.log`.

## Демонстрация и критерии оценки

![Полный сценарий ValutaTrade Hub](docs/demo.gif)

[Запись asciinema](docs/demo.cast) · [Текст сеанса](docs/demo.txt) ·
[Команды сценария](docs/demo.commands) · [Проверка критериев](docs/assessment.md)

GIF записан с окна Terminal на macOS при автоматическом выполнении сценария.
Демо использует настоящий интерактивный CLI с запросами к CoinGecko и
ExchangeRate-API. Оно показывает регистрацию и вход, пустой портфель, пополнение
USD, обновление курсов, покупку BTC и EUR, продажу BTC, оценку портфеля в USD/EUR,
прямой и обратный курс, фильтры `show-rates`, нехватку средств, неизвестную валюту,
отрицательную сумму и отказ в доступе после `logout`.

Запись использует отдельный временный каталог и тестовую учетную запись `demo`.
Реальные счета пользователя не меняются. API-ключи не записываются в демо.
Цены и время в записи отражают момент ее создания, а не текущий рынок.

Файл совместим с [форматом asciicast v2](https://docs.asciinema.org/manual/asciicast/v2/).
Если установлен asciinema, его можно воспроизвести командой:

```bash
asciinema play docs/demo.cast
```

Для повторной записи на macOS/Linux настройте `.env` или переменные окружения:

```bash
uv run python scripts/record_demo.py --live
```

Можно использовать `--prompt-key` для скрытого ввода ключа ExchangeRate-API.
Флаг `--live` показывает команды и ответы приложения в текущем терминале.
Скрипт создает `docs/demo.cast` и `docs/demo.txt`, проверяя успешное выполнение
основных шагов. Если источник недоступен, успешная запись не подменяется
придуманными ответами. Пауза между командами задается через `--pause`.

Из `.cast` можно отдельно создать GIF с текстовым оформлением, без записи окна;
Pillow нужен только для подготовки изображения:

```bash
uv run --with pillow python scripts/render_demo.py
```

## Проверки и сборка

| Действие | Через uv | Через Make |
| --- | --- | --- |
| Установка | `uv sync` | `make install` |
| Запуск | `uv run wallet` | `make run` или `make wallet` |
| Альтернативный запуск | `uv run project` | `make project` |
| Линтер | `uv run ruff check .` | `make lint` — обе проверки |
| Проверка форматирования | `uv run ruff format --check .` | `make lint` — обе проверки |
| Форматирование | `uv run ruff format .` | `make format` |
| Тесты | `uv run python -m unittest discover -s tests -v` | `make test` |
| Сборка wheel и sdist | `uv build` | `make build` |

Тесты используют временные папки. Они проверяют модели, изоляцию пользователей,
сохранение данных, сделки, срок кэша, ошибки файлов и реальные запуски CLI,
наследование валют, Singleton, конкурентные обновления, исключения,
состав записей журнала и его ротацию, API-контракты, отсутствие ключей в ошибках,
частичные отказы источников, историю курсов и параллельные процессы парсера.
Сетевые ответы в тестах подменяются; личные ключи для запуска тестов не нужны.
Это тесты проекта, а не предоставленные преподавателем автотесты.

Сборка и установка wheel на macOS/Linux:

```bash
uv build
uv pip install --python .venv/bin/python dist/*.whl
.venv/bin/wallet
```

Прямой запуск `.venv/bin/wallet` проверяет установленный пакет. Для возвращения
к разработке выполните `uv sync`: изменения исходников снова будут доступны
без переустановки wheel.

Добавление зависимостей: `uv add <пакет>` или `uv add --dev <инструмент>`.
Модули стандартной библиотеки отдельно устанавливать не требуется.
